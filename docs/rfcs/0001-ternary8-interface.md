# RFC 0001 삼진 내적 회로의 연산 및 외부 인터페이스

- Status: Draft
- 대상 모듈: `v_ternary8_top`

## What

길이 8의 삼진 가중치 내적 회로에 대해 연산 범위, 입력·출력 형식, 오류 처리와 리셋 동작을 정리합니다. 근거는 김태완의 「My Chip 설계 실습 안내서」(2026.10.18) 6~7쪽과 20~23쪽, 현재 `src/` 구현입니다. 가이드에서 제시한 요구사항과 현재 구현을 대조하기 위한 초안이며, 팀의 RFC 승인이나 구현의 검증 완료를 뜻하지 않습니다.

안내서의 '팀 3'은 삼진 내적 주제의 구분입니다. 이 RFC가 속한 저장소와 팀 식별자는 Circuit Team 05로 유지합니다.

## Why

송신 FPGA, RTL 구현과 테스트벤치가 같은 동작 규칙을 사용해야 합니다. 코드 설명과 팀에서 합의한 요구사항을 구분하고, 검증 시 정답과 합격 조건을 판단할 기준을 마련합니다.

## How

### 연산 범위와 인코딩

```text
y = Σ wi·ai, i = 0…7

ai: 2의 보수 signed 8비트 정수, −128…+127
wi: −1, 0, +1
y : −1024…+1024
```

최댓값 +1024는 signed 11비트로 표현할 수 없으므로 결과는 signed 12비트로 표현합니다. 입력을 12비트로 부호 확장한 후 가중치에 따라 0, +a 또는 −a를 생성합니다. 따라서 입력 −128에 가중치 −1을 적용한 항은 +128입니다.

| 가중치 코드 | 의미 | 항의 값 |
| --- | --- | --- |
| `00` | 0 | 0 |
| `01` | +1 | +a |
| `10` | −1 | −a |
| `11` | 불법 | 0으로 계산하고 오류를 기록 |

### 입력 통신

모든 수신은 클록 상승 에지에서 수행합니다. `RST_N=1`인 정상 동작 중 `IN_VALID && IN_READY`일 때 `IN[3:0]`의 한 조각을 수신합니다. 송신 측은 수신 에지에 맞춰 데이터와 유효 신호를 안정시키고, 수신되지 않은 조각을 다음 수신 기회까지 유지합니다.

한 바이트는 하위 4비트, 상위 4비트 순서로 전송합니다. 한 작업의 바이트 순서는 다음과 같습니다.

```text
W0 → W1 → a0 → a1 → a2 → a3 → a4 → a5 → a6 → a7

W0 = {w3, w2, w1, w0}, 1바이트
W1 = {w7, w6, w5, w4}, 1바이트
```

작업 하나는 총 10바이트, 4비트 조각 20개입니다. 구분용 명령이나 태그는 없으며 수신 순서로 용도를 판별합니다. 현재 RTL은 한 바이트를 완성한 뒤 처리하는 한 클록 동안 `IN_READY`를 0으로 내립니다. 입력 사이에 `IN_VALID=0`인 공백을 허용하며, 현재 수신 상태는 유지합니다.

### 출력 통신

마지막 입력 a7을 처리할 때 해당 항까지 포함한 합과 오류를 저장합니다.

```text
RESULT[15:13] = 000
RESULT[12]    = 불법 가중치 오류 플래그
RESULT[11:0]  = signed 내적 결과
```

`OUT_VALID=1`인 연속 네 클록 동안 아래 순서로 전송합니다. 수신 측은 각 상승 에지에서 한 조각을 수신합니다.

```text
RESULT[3:0] → RESULT[7:4] → RESULT[11:8] → RESULT[15:12]
```

별도 `OUT_READY`가 없으므로 출력 전송을 멈출 수 없습니다. 출력 중에는 `IN_READY=0`이며, 출력 완료 후 다음 작업의 W0부터 수신합니다. 출력이 유효하지 않을 때 `OUT` 값은 수신 데이터로 해석하지 않습니다.

가이드의 외부 응답 상한은 마지막 입력 조각을 수신한 상승 에지부터 첫 출력 조각을 수신하는 상승 에지까지 32클록 이내입니다. 실제 RTL의 에지별 지연은 테스트벤치에서 측정하여 확인합니다.

### 오류 처리

가중치 코드 `11`은 해당 항을 0으로 처리하고 오류 플래그를 1로 설정합니다. 그 작업의 나머지 항은 계속 계산하며, 오류는 작업 종료까지 유지합니다. 마지막 가중치 w7에서 발생한 오류도 출력에 포함합니다.

새 작업의 W0 바이트를 처리할 때 이전 누산값과 오류를 초기화합니다. 따라서 이전 작업의 오류나 합이 다음 결과에 남지 않습니다.

### 리셋

`RST_N`은 동기식 active-low 신호입니다. `RST_N=0`인 상승 에지에서 초기화하고, 같은 에지의 데이터 수신·누산·출력 동작보다 리셋을 우선합니다.

가이드에 따라 송신 측은 `RST_N=0`을 최소 네 번의 상승 에지 동안 유지합니다. 하강 에지에서 `RST_N=1`로 해제하고 두 클록 후 새 작업을 입력합니다. 테스트벤치도 입력을 하강 에지에 갱신하고 수신 여부를 상승 에지 기준으로 판단합니다.

- 수신 중인 반 바이트와 진행 중인 작업을 버립니다.
- 가중치, 누산값과 오류 플래그를 초기화합니다.
- 진행 중인 출력을 중단하고 `OUT_VALID`를 0으로 만듭니다.
- 컨트롤러는 W0 수신 상태로 돌아갑니다. 송신 측도 새 작업을 W0부터 다시 보냅니다.

현재 RTL은 리셋 중 `IN_READY=0`을 보장하지 않습니다. 송신 측은 리셋 에지에서 보이는 `IN_READY`를 데이터 수신의 근거로 사용하지 않습니다.

## 검증 근거와 승인 전 확인 사항

현재까지 안내서와 RTL 소스를 검토했으며, 이 RFC에 대한 시뮬레이션 검증은 아직 수행하지 않았습니다. 승인 전에 다음 항목을 확인합니다.

- 공식 제출 가이드의 포트, 인코딩, 전송 순서 및 리셋 규칙과 일치하는가?
- 가이드의 불법 코드 처리와 작업별 오류 초기화가 구현·기준 모델에 정확히 반영되었는가?
- 송신·수신 FPGA가 입력 수신 허용 규칙과 멈춤 없는 네 클록 출력을 지원하는가?
- 가이드의 리셋·재시작 절차와 진행 중 작업 폐기를 테스트에서 확인했는가?
- 바이트 처리 지연과 최종 입력부터 첫 출력 수신까지의 지연이 실제 에지표 및 32클록 상한과 일치하는가?

RFC를 검토하는 PR에서 합의한 뒤 Status를 Accepted로 바꾸고, 확정한 규칙에 맞춰 테스트를 작성합니다. 현재 구현과 다른 규칙을 채택하면 관련 RTL과 검증 코드도 함께 갱신합니다.
